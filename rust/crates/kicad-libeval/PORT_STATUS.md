# kicad-libeval: port status

Port of KiCad's two expression evaluators: the LIBEVAL compiler/VM used by custom DRC rules
and the `NUMERIC_EVALUATOR` used by numeric input fields. The board binding (pcbnew
`PCBEXPR_*`) is not part of this crate; it belongs to `kicad-drc`.

## Differential oracle

`tests/oracle/` (see its `README.md`) builds KiCad's own Lemon, generates the parsers from the
unmodified grammar files and links two drivers against the unmodified
`libeval_compiler.cpp`, `numeric_evaluator.cpp`, `string_utils.cpp`, `eda_units.cpp`.
Each case records `Compile()` result, error stage/offset/message, every error callback,
`CreateVarRef`/`CreateFuncCall` calls, the UCODE dump, the syntax tree as built by the Lemon
parser (op, srcPos, flags, string, leaves), `Run()` results (type, units, IEEE bits, string)
with and without error callback, run-time errors, deferred side effects.

| Golden | Cases | Status |
|---|---|---|
| `libeval_golden.txt` (hand-written `libeval_cases.txt`) | 1595 | bit-identical |
| `libeval_fuzz_hashes.txt` (all 1-3 token sequences, all 4-token sequences of a grammar alphabet, random token soups, random well-formed expressions) | 28420 | all match |
| `numeric_golden.txt` (`numeric_cases.txt`) | 1322 | bit-identical |
| `numeric_fuzz_hashes.txt` | 8219 | all match |

The parse tables embedded in both `grammar.rs` files were re-generated with the real Lemon
and checked identical to the embedded ones (2026-11-09).

## Deviations

- Locale: there is none (PORTING.md section 5). Decimal separator is always `.`, ctype
  classification is ASCII ("C" locale), case-insensitive comparison uses the Unicode simple
  case mapping (what `towlower`/`towupper` do in a UTF-8 locale). The oracle runs with
  `LC_ALL=C.UTF-8`.
- C++ undefined behaviour made deterministic: reusing a `COMPILER` after a lexical error (or a
  third compile after any error) reads freed parser-stack memory in C++; the Rust port resets
  cleanly. `NUMERIC_EVALUATOR` division by zero leaves the C++ result text indeterminate; Rust
  yields a deterministic (invalid) result.
- API shape: `VALUE::AsDouble/AsString/EqualTo` take the `Context` explicitly; deferred
  evaluation closures receive the context instead of capturing `CONTEXT*`. Virtual methods of
  `UCODE`, `VAR_REF`, `VALUE` and `CONTEXT` subclasses are provided through the `UcodeBinder`
  trait (`Env`, `Custom`, `VarRef` associated types). `Context::reset` does not reset `Env`
  (C++ `PCBEXPR_CONTEXT::Reset` is an override; the caller resets `env_mut()` itself).
- `UCODE::Dump` prints `PUSH VAR [<address>]` like C++; the addresses differ by nature and
  the oracle comparison normalises them.
- Lemon tracing (`ParseTrace`) and coverage instrumentation are not ported.

## Known gaps

- The pcbnew binding (`PCBEXPR_*`, property introspection, `pcbexpr_functions.cpp`) is the
  job of `kicad-drc`; 20 ported C++ test cases wait for it.
