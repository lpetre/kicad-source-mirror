# PCBIO-17: Corpus differential harness for the board reader / writer

Crate: kicad-pcb

Specification: rust/docs/analysis/pcb-io.md section 9 (validation design D0-D3: normalise each corpus board ONCE with the reference kicad-cli (`pcb upgrade --force`, on copies) to get O1; then compare rust(O1) with oracle(O1) byte for byte; legacy inputs without UUIDs are compared after UUID masking) and the PCBIO-17 row. You own rust/crates/kicad-pcb/tests/io_corpus.rs (+ helper modules under tests/io_corpus/), a script rust/tools/io-corpus/run.sh (+ README), and additions to rust/crates/kicad-qa (helpers mirroring qa/pcbnew_utils/board_file_utils.cpp; the UUID canonicaliser).
Build the harness that will drive the remaining parser / writer packages: (1) oracle cache: for every corpus board (qa/data/pcbnew, demos; skip list for the very large ones and the known-bad file) produce O1 and O2 = oracle re-save of O1 under rust/target/io-corpus/ (never in the repository; skip silently when the oracle is absent; run kicad-cli with a private KICAD_ORACLE_HOME, 2 at a time at most, nice'd); record which boards are fixed points (O1 == O2) - only those are byte-exact targets. (2) Rust side: parse O1 with allow_pending and format with allow_pending; compute per board: byte-identical yes/no; else the first differing line with context; the list of skipped (pending) constructs on both sides. (3) A scoreboard: boards identical / differing / failing to parse / with pending constructs, plus a histogram of pending tokens and of first-difference tokens, written to rust/target/io-corpus/scoreboard.md and printed; `run.sh --board NAME` for a single board with a unified diff. (4) Commit a SMALL golden set (a dozen boards under 100 KB chosen to cover different format versions: O1 text + expected status) under tests/golden/io_corpus/ so that `cargo test -p kicad-pcb` without the oracle still checks them (tests for boards that cannot pass yet are #[ignore]d with the pending package named). (5) Also wire the item-level comparison: for a board, run pcb-dump (--no-init) and pcb-dump-rs and feed compare.py, summarising sections; expose it as `run.sh --dump NAME`.
Run it once and report the scoreboard as it stands (most constructs will be pending: that is expected). The harness must be cheap to re-run (cache keyed by file hash and oracle binary mtime).
