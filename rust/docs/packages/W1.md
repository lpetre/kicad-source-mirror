# W1: Session, CLI and WebAssembly skeletons with a working wasm pipeline

Crate: kicad-session, kicad-cli, kicad-wasm

The user's hard requirement is that the port builds and runs as WebAssembly; this package proves the whole pipeline now and gives every later package a place to plug into. Read rust/docs/THIRD_PARTY_EQUIVALENTS.md section 4 (the verified wasm toolchain: wasm-bindgen =0.2.130, wasm-bindgen-cli 0.2.130 is installed, node 22 at /opt/node22/bin/node), rust/docs/design/board-model.md section 14 (wasm / JS story) and the 'kicad-session' decision in its section 17, rust/docs/analysis/drc.md and plot-fab.md section 1 (the kicad-cli flows and option defaults).
Create three new crates under rust/crates/ (the workspace picks them up through its `crates/*` glob; you own them entirely):
1. kicad-session (lib): `Session { board, .. }` as the single owner object the CLI and wasm layer use; for now the loading entry points (`Session::load_board(text, source_name, project_json: Option<&str>, rules_text: Option<&str>)`) call kicad_pcb::io::parse_board if it exists when you get there (another agent is writing it right now) and otherwise return a clear 'pending' error behind one function; the job structs with all their fields and defaults ported from common/jobs/job_pcb_drc.h, job_export_pcb_gerbers.h (+ job_export_pcb_gerber.h, job_export_pcb_plot.h), job_export_pcb_drill.h, job_export_pcb_svg.h, job_pcb_upgrade / job_fp_upgrade and the base JOB / JOB_RC classes as far as headless use needs; one `run_*` function per job returning a structured result (files as (name, bytes) pairs, report text, exit code as in pcbnew/pcbnew_jobs_handler.cpp) - bodies call into kicad-drc / kicad-fab / kicad-zone when those exist; until then they return a typed `NotYetPorted { subsystem }` error. No filesystem access in this crate (wasm).
2. kicad-cli (bin `kicad-rs`, native only): clap 4 command tree mirroring the reference kicad-cli exactly for `version`, `pcb drc`, `pcb export gerbers`, `pcb export drill`, `pcb export svg`, `pcb upgrade`, `fp upgrade`: every option, short name, default, validation rule, message text and exit code from kicad/cli/command_pcb_drc.cpp, command_pcb_export_gerbers.cpp, command_pcb_export_drill.cpp, command_pcb_export_svg.cpp, command_pcb_upgrade.cpp, command_fp_upgrade.cpp, command_pcb_export_base.cpp and kicad/cli/exit_codes.h (compare `--help` output and error behaviour with the oracle wrapper; clap's help layout may differ, option semantics may not). It does the file I/O (read board, sibling .kicad_pro / .kicad_dru, write outputs), fills the job struct and calls kicad-session. Integration tests run the binary on corpus boards and assert the 'not yet ported' paths for now, structured so they turn into real comparisons against the oracle later.
3. kicad-wasm (cdylib + rlib, wasm-bindgen): the JavaScript API. Design the final surface now (document it in rust/crates/kicad-wasm/README.md): `version()`, `loadBoard(text, {project, rules, name}) -> Board` (a JS class wrapping a Session), `board.runDrc(options) -> report object + text`, `board.exportGerbers(options) -> [{name, content}]`, `board.exportDrill(options)`, `board.plotSvg(options) -> string`, `board.save() -> string`, `board.ratsnest()`, `board.refillZones()`, item access for clients such as an autorouter (`board.nets()`, `board.tracks()`, `board.addTrack({...})`, `board.addVia({...})`, `board.remove(id)` with ItemId::to_bits numbers as handles). Implement for real everything that the already-ported crates support so the pipeline is exercised end to end today: version, `prettify(text)` (kicad-sexpr), a `tokenStats(text)` lexer call, `strokeText(text, sizeMm) -> SVG path data` (kicad-font), `polygonBoolean(a, b, op)` on point arrays (kicad-geom ShapePolySet with the vendored Clipper2), `plotDemoGerber()` (kicad-plot: a small Gerber file produced by the Rust Gerber plotter), and loadBoard as far as the parser has landed; the rest returns a typed 'not yet ported' JS error. console_error_panic_hook installed; no getrandom unless needed (then the wasm_js feature only in this crate).
Build + test pipeline (all committed, all run by you and green): rust/scripts/build-wasm.sh (cargo build -p kicad-wasm --target wasm32-unknown-unknown --profile wasm-release; wasm-bindgen for --target nodejs into rust/web/pkg-node and --target web into rust/web/pkg; print .wasm size; run wasm-opt if available, otherwise say so), rust/web/test/smoke.mjs (node: load the nodejs package, call every implemented API, assert results - e.g. prettify of a corpus board equals the native result, the polygon boolean result equals a value you computed natively), rust/web/index.html + rust/web/app.js (a small demo page: drop a .kicad_pcb, show the token statistics / prettified size now, with clearly marked placeholders for DRC and Gerber export), rust/web/test/browser.mjs (Playwright with the pre-installed Chromium - `require('playwright')` works from any directory, do NOT install anything - serving rust/web from a local static server and asserting that the page loads the wasm and reports a result), and a native-vs-wasm equality test for the implemented calls. Add rust/web/pkg, rust/web/pkg-node to rust/.gitignore if not covered. Also verify that EVERY library crate of the workspace builds for wasm32-unknown-unknown today (`cargo build --target wasm32-unknown-unknown -p <crate>` one by one for kicad-sexpr, kicad-core, kicad-geom, kicad-font, kicad-libeval, kicad-plot, kicad-pcb, kicad-drc, kicad-fab, kicad-zone, kicad-connectivity) and report any that does not.
Self-verification here means: the scripts above run green, and the wasm results equal the native results.
