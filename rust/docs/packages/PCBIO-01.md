# PCBIO-01: Board file parser core and board skeleton

Crate: kicad-pcb

Specification: rust/docs/analysis/pcb-io.md (read the precedence note at the top, sections 1-5 and 7, and the PCBIO-01 row of section 10) and rust/docs/design/board-model.md sections 0-9 and section 13 'Parser' (create / fill / attach: footprints and tables are created in place with create_footprint / footprint_add / attach_footprint; arena insertion order = file order). You own rust/crates/kicad-pcb/src/io/ (mod.rs plus a parser/ directory).
C++: pcbnew/pcb_io/kicad_sexpr/pcb_io_kicad_sexpr_parser.h and the ranges of pcb_io_kicad_sexpr_parser.cpp the analysis document assigns to PCBIO-01 (helpers incl. parseBoardUnits / parseXY / parseHex / parseBool variants / parseKIID handling and the version-dependent helpers, Parse, finishItem, parseBOARD and its unlocked body with ALL its post-processing, parseHeader, parseGeneralSection, parsePAGE_INFO, parseTITLE_BLOCK, parseLayers incl. legacy layer handling and user-defined layers, net declarations, properties, the error messages incl. FUTURE_FORMAT_ERROR and 'This file does not contain a PCB.'). Use kicad_sexpr's DsnLexer with the generated pcb keyword table (PcbKeysT) exactly as the C++ uses PCB_LEXER (token classes matter: keyword vs quoted string vs number).
Deliver: `kicad_pcb::io::parse_board(text, source_name, &ParseOptions) -> Result<Board, IoError>` (and the entry for footprint files as a stub for PCBIO-14). The other top-level and nested constructs belong to later packages: create one file per later package NOW with the parse function signatures they will fill (parser/tracks.rs + parser/shapes.rs: PCBIO-03; parser/setup.rs: PCBIO-04; parser/text.rs: PCBIO-05; parser/footprint.rs: PCBIO-06; parser/pad.rs: PCBIO-07; parser/zone.rs: PCBIO-08; parser/group.rs: PCBIO-09; parser/dimension.rs: PCBIO-10; parser/netclass_embedded.rs: PCBIO-11; parser/misc_items.rs: PCBIO-12; parser/generator.rs: PCBIO-13; parser/fp_lib.rs: PCBIO-14), each body being a staging stub: with `ParseOptions::allow_pending == false` (default) it returns an IoError 'port pending: <token> (PCBIO-nn)'; with allow_pending == true it skips the balanced s-expression and records (token, line) in a `ParseReport::skipped` list returned next to the board, so the corpus can be parsed end to end while the other packages land. The shared parser state struct and helper API those packages need (current token, expect / need helpers, required-version checks, unit conversion, layer lookup, net lookup by name / legacy code, deferred group / UUID bookkeeping) must be complete and documented in notes_for_next.
Model calls: Board construction, layers, nets (add_net / NETINFO_LIST::AppendNet semantics), properties, title block and page are model packages M1 / M3 / M22 that are being ported right now; call their API (stubs panic until they land; re-run your tests when they do).
When your parser works, replace the body of `load_board_for_dump` in src/bin/pcb_dump_rs.rs (owned by the DUMP-RS agent, but this one function is yours once it exists; if the file is still a bare placeholder, add the function) with a call to parse_board(allow_pending = true).
Tests: the header / general / layers / nets of ALL corpus boards (kicad_qa::pcbnew_data_dir() and demos_dir(), ~375 files; the four very large ones in an #[ignore] test) parse with allow_pending; the error cases; qa/tests/pcbnew/pcb_io/kicad_sexpr/test_kicad_sexpr.cpp cases that concern your part (ScientificNotationLoading etc.). Oracle: compare the `board` section (layers, nets, title block, page, properties) of `pcb-dump board --no-init --sections board` with pcb-dump-rs on a few dozen small boards using rust/tools/pcb-dump/compare.py (fields that depend on unported packages show as pending - that is fine; mismatches are not).
