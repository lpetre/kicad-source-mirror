# M26: Generated tables (drill chart, stackup table, board characteristics) and their refresh

Crate: kicad-pcb (src/pcb_generated_table.rs, new modules for the table models / schema /
drill chart, src/pcb_drill_map.rs for the drill-symbol parts it needs), then the call sites
in kicad-session (board_loader.rs RefreshGeneratedTables, jobs_handler.rs) - minimal edits

The reference refreshes every generated table of a board at load
(pcbnew/board_loader.cpp L189), before plotting (pcb_plotter.cpp L90,
pcbnew_jobs_handler.cpp L1833 / L2294) and in `pcb upgrade` (L3330:
`RefreshGeneratedTables( *brd ) > 0` marks the board as changed). The port keeps generated
tables as data only: `kicad-session` returns NotYetPorted (M26) as soon as a board holds
one, so such boards cannot be loaded, upgraded or plotted (corpus:
qa/data/pcbnew/api_kitchen_sink and the boards the Gerber job corpus lists as pending on
RefreshGeneratedTables), and a parse-only re-save differs in the drill chart cells
("0.30" vs "0.30 mm").

C++ to port, statement by statement (about 4,700 lines; read the board model design
rust/docs/design/board-model.md sections 0-9 and 16-17 and the PORT_STATUS.md sections of
M11 (tables), M23 (small items incl. drill maps, generated tables as data), PCBIO-12 (their
parser / writer) and FAB-01 (drill model in kicad-fab: hole lists and tools - the drill
