# M25a: Barcode model without symbol encoding

Crate: kicad-pcb

Your Rust module (the only file you edit): src/pcb_barcode.rs.

Boards that contain a barcode currently cannot be loaded or saved: the parser and writer
(package PCBIO-12, done) call PCB_BARCODE methods that are still `port_pending!` stubs
(SetPosition, GetPosition, GetAngle, Rotate, SetLayer, AssembleBarcode ...).

C++ to port: pcbnew/pcb_barcode.cpp + pcb_barcode.h - everything EXCEPT the symbol encoding
itself: position / angle / size / margin / text / kind / error-correction accessors and
setters with their side effects, Move / Rotate / Flip / Mirror, SetLayer, the knockout and
"show text" handling, the text item of the barcode (it is its own EdaTextItem host per the
design: read rust/docs/design/board-model.md 6.2a and the kernel review notes in
PORT_STATUS.md), GetBoundingBox, GetEffectiveShape / TransformShapeToPolygon working on the
assembled polygon, Compare (package M22 asks for PCB_BARCODE::Compare: board/compare.rs has a
local stub - list the call site in change_requests once yours exists), item description,
operator== if cheap. AssembleBarcode: port the complete assembly logic around the encoder
(scaling of the symbol to the requested size, margins, the knockout box, text placement,
rotation, the polygon union with its Clipper calls) and isolate the single call into the zint
library (ZBarcode_Encode / the module matrix it yields) behind one function
`encode_symbol(kind, text, error_correction) -> Option<ModuleMatrix>` that returns `None`
("encoder not available") for now: with `None` the barcode assembles exactly as the C++ does
when zint fails to encode (check that path: what polygon and bounding box result) and the gap
is recorded. Do NOT add an encoder dependency in this package; describe in PORT_STATUS.md what
a faithful encoder needs for each barcode kind KiCad offers (which zint symbologies and
options the C++ selects), so a later package can add them.

Model package rules: the board model design is fixed and reviewed
(rust/docs/design/board-model.md: read sections 0-9, 12, 15 and 16; board-model-types.md for
PcbBarcode; rust/crates/kicad-pcb/PORT_STATUS.md). Every method already exists with its final
signature as a port_pending! stub: replace the stubs with faithful ports and keep the
signatures. Frozen (report needed changes): lib.rs, items_macro.rs, ids.rs, arena.rs, cache.rs,
item.rs, traits.rs, ctx.rs, item_ref.rs, pending.rs, drc_api.rs, test_support.rs,
foundation_stub.rs, Cargo.toml and every other package's files.
`python3 crates/kicad-pcb/tools/check_item_shims.py` must stay ok.

Verification: (1) the stored members and frame handling against `pcb-dump board --no-init
--sections item,misc,bbox` on COPIES of the corpus boards with barcodes (grep -l '(barcode'
under qa/data/pcbnew and demos) through pcb-dump-rs + rust/tools/pcb-dump/compare.py: zero
mismatches for everything that does not depend on the encoded symbol; list the fields that do;
(2) byte level: those boards must now round-trip through the Rust parser and writer exactly
like the reference `kicad-cli pcb upgrade --force` re-save (the PCBIO-12 oracle
tests/pcbio12_misc_items.rs has barcode cases waiting; the io-corpus harness
rust/tools/io-corpus/run.sh shows the boards); (3) port
qa/tests/pcbnew/test_barcode_load_save.cpp as far as it does not need the encoded symbol.
